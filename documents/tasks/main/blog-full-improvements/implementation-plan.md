# 블로그 전면 개선 구현 계획

## 사용자 요청

- 현재 블로그에서 제안한 개선 사항을 모두 구현한다.
- 기존 작업 트리 변경사항은 보존한다.
- 커밋은 생성하지 않는다.

## 목표

1. 대량 콘텐츠 환경에서 카테고리와 검색 탐색 비용을 줄인다.
2. 포트폴리오와 대표 기술 글을 첫 화면에서 찾을 수 있게 한다.
3. 태그 taxonomy의 검색엔진 노출과 추천 노이즈를 줄인다.
4. 공유 이미지, 구조화 데이터, 콘텐츠 이미지 성능을 개선한다.
5. PR 단계에서 빌드·메타데이터·링크·페이지 크기 회귀를 탐지한다.

## 기준선

- 게시글 755개
- 프로덕션 빌드 3,298 pages / 4,478 HTML / 88MB
- 검색 인덱스 3.38MB(raw), 약 1.07MB(gzip)
- 카테고리 첫 페이지: log 596KB, study 491KB
- 태그 약 1,244개, 단일 게시글 태그 905개
- 기존 빌드는 성공하지만 PaperMod에서 Hugo deprecated 경고 2건 발생

## 핵심 트레이드오프와 결정

### 카테고리 필터

- 전체 DOM을 렌더한 뒤 숨기면 필터는 즉각적이지만 초기 HTML이 지나치게 크다.
- 결정: 카테고리는 서버 페이지네이션으로 되돌리고, 시리즈 필터는 실제 series taxonomy 링크로 제공한다. JavaScript 의존성과 공유 불가능한 필터 상태를 제거한다.

### 태그 정리

- 755개 문서의 frontmatter를 일괄 수정하면 사용자 콘텐츠에 큰 변경이 발생한다.
- 결정: 이번 구현에서는 태그/태그 term 페이지를 `noindex, follow`로 전환하고 태그 목록을 사용 빈도 기준으로 정리한다. 기존 태그 값은 보존하며, 신규 콘텐츠 가이드와 자동 검증으로 재발을 막는다.

### 검색 인덱스

- 본문 전문은 recall이 높지만 초기 다운로드가 크다.
- 결정: 기본 인덱스는 title, description, headings, categories, tags, series로 구성하고 필터를 제공한다. 본문 전문은 제외해 초기 비용과 검색 노이즈를 줄인다.

### OG 이미지

- 단순 SVG는 결정적이지만 소셜 미리보기 호환성을 위해 래스터 결과가 안전하다.
- 결정: 1200×630 PNG를 생성해 사이트 기본 OG 이미지로 사용한다.

### 이미지 처리

- 외부 CDN 이미지는 Hugo image pipeline에서 직접 크기 변환하기 어렵다.
- 결정: Markdown 렌더 훅에서 lazy/async decoding을 적용하고, 작성자가 width/height를 전달할 수 있게 한다. raw HTML 이미지의 전면 자동 변환은 기존 표현 손상 위험 때문에 검증 정책으로 관리한다.

## 구현 단계

1. 홈 대표 콘텐츠·포트폴리오 진입점 추가
2. 카테고리 목록을 서버 페이지네이션과 series 링크로 변경
3. 검색 인덱스 경량화 및 taxonomy 필터 추가
4. 태그 페이지 noindex와 태그 허브 정리
5. OG 이미지와 Person/WebSite 구조화 데이터 보완
6. 이미지 렌더 훅, CSS/JS 자산 경량화, 접근성 보완
7. PR 빌드·검증 스크립트·페이지 크기 예산 추가
8. 프로덕션 빌드 및 생성물 정적 검증

## 완료 조건

- Hugo 프로덕션 빌드 성공
- 카테고리 첫 페이지가 서버 페이지네이션으로 제한됨
- 검색 인덱스가 기준선보다 작아지고 taxonomy 필터가 동작 가능한 데이터 포함
- 태그 페이지가 noindex이며 sitemap 제외 상태 유지
- 홈과 메뉴에서 포트폴리오 접근 가능
- 1200×630 기본 OG 이미지 적용
- CI가 pull request에서 빌드와 저장소 검증 수행
- 커밋이 생성되지 않음
